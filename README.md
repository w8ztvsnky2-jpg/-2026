# Service-Level Agreement (SLA) для управления Issues и PR

## 1. Введение
Этот документ описывает обязательства команды по обработке обращений (Issues) и запросов на слияние (Pull Requests) для проекта. Наша цель — обеспечить прозрачность и предсказуемость взаимодействия с сообществом[citation:8][citation:11].

## 2. Приоритеты и время реакции
Мы используем следующие уровни приоритета для классификации задач[citation:6].

| Приоритет | Описание | Время первого ответа | Целевое время решения |
| :--- | :--- | :--- | :--- |
| **P1 (Критический)** | Проблема, блокирующая работу (падение сервиса, уязвимость). | 4 часа[citation:7][citation:11] | 24 часа |
| **P2 (Высокий)** | Серьезный баг, влияющий на функциональность. | 8 часов[citation:1] | 72 часа |
| **P3 (Средний)** | Ошибки, не влияющие на основные функции, запросы на улучшение. | 24 часа[citation:1][citation:7][citation:13] | 5 рабочих дней |
| **P4 (Низкий)** | Вопросы, документация, мелкие доработки. | 48 часов[citation:8][citation:13] | 10 рабочих дней |

*   **Время первого ответа**: период до получения подтверждения от команды[citation:8].
*   **Целевое время решения**: период до закрытия задачи или предоставления рабочего решения.
*   **Сроки для Pull Requests**: мы стремимся дать первый отзыв в течение **48 часов** и провести полный ревью в течение **1 недели**[citation:11][citation:13].

## 3. Эскалация
Если вопрос не решен в установленный срок, вы можете отметить тикетом (`@`) мейнтейнера в issue/PR или написать на почту: **support@ваш-проект.com**[citation:8].

## 4. Процедура и исключения
*   **Сопровождение**: для багов и фич мы используем стандартные шаблоны `.github/ISSUE_TEMPLATE`[citation:6].
*   **Исключения**: SLA не применяется к вопросам, вызванным форс-мажором, действиями пользователя или использованием неподдерживаемых версий[citation:1][citation:4].

### 💡 Как адаптировать под себя
Этот шаблон можно легко настроить:
*   **Уровни приоритета**: [Приоритеты для GitHub и коды ошибок](https://stackoverflow.com/questions/57080860/priority-levels-for-github-issues) — здесь описано, как задать свои уровни.
*   **Инструменты**: Посмотрите `api-sla-editor` для автоматизации[citation:9].
*   **Управление**: Ознакомьтесь с гайдом по управлению SLA в опенсорсе[citation:3][citation:7].
*   **Юридическая форма**: Если вам нужен полноценный юридический документ, используйте шаблоны на GitLaw[citation:14] или Common Paper[citation:4].

Если нужна помощь в настройке этих метрик для вашего конкретного стека, просто спросите!
